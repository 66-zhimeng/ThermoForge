# Active Plan

## Objective

让模型实验室（`category=lab`）成为**自治**通路：Agent 自己写模型代码、自己在
真实数据上训练与测试、自己读指标改代码，闭环里不含任何人工审批环节。

## Assumptions

- 可复现性由机器判定保证，不由人工审批保证：五连检（接口 / 拟合预测 /
  save 契约 / save-load 往返位级一致 / 同种子重训位级一致）+ 环境锁 +
  子进程隔离 + 源码内容哈希。
- 「这个建模假设好不好」由证据淘汰，不由人排队放行；因此 `validated` 即可
  进正式实验，`deprecate` 是事后否决且不阻塞任何一轮循环。
- **预处理审批的人工门禁保持不变**：它改的是数据（会产生 vault revision），
  与实验室改假设不是一回事（DD-02 修订记录，2026-08-17）。
- 静态扫描是候选代码执行前唯一的自动关卡，是粗筛不是内核沙箱；该风险敞口
  明知并接受（同上）。
- 改模型 = 提交新版本（内容哈希一变即 `v(N+1)`），历史实验因源码快照冻结在
  实验目录而不被改写。

## 提示词装载（本次一并修复）

发现四个位点没有一个真正走 `prompts.load()`：`agent.py._default_system_prompt()`
直接读 `system.md` 原文（技能不进提示词），副驾与规划器各用代码内常量
（`copilot.md`/`planner.md` 无人读取），`mcp.md` 根本不存在。`prompts.py`
承诺的「装技能 = 改文件，四处行为一致」一处都没兑现，技能书成了死文档。

修法：四个位点统一走 `prompts.load()`，代码内常量降级为文件缺失时的兜底；
`load()` 增加 `$name` 占位符填充（`safe_substitute`），只用于**代码派生的
事实**（页面清单、界面工具名），决策规则一律写死在文件里；补上 `mcp.md`。
回归测试用哨兵文件替换 `PROMPTS_DIR`，验证四个位点都跟着变。

装载后的提示词规模（含绑定技能）：cli ≈ 7.4k tokens、planner ≈ 6.5k、
mcp ≈ 6.6k、copilot ≈ 0.7k（副驾不绑技能）。mcp 那份进的是 MCP 握手的
`instructions`，对每个外部 agent 会话都生效——嫌重就把 `SKILL_BINDINGS["mcp"]`
改成 `()`，一行的事。

## 冷机 / 板换建模：以 R²≥0.95 为目标（2026-08-17）

判据面取 `rolling_cv` 折间均值（RG-0012 / RG-0013 的 `evaluated_on`）。
约束：静态 what-if 用途，禁功率滞后项；**`runtime_accum` 不得作为自变量**
（需求方 2026-08-17 明确：累计运行时长是时间代理，不可操纵且必然外推）。

**目标未达成，判定为结构性不可达。** `R² = 1 − (CVRMSE/CV_y)²`，评估窗内
`CV_y` 只有 0.11~0.14，R²=0.95 要求 CVRMSE 降到 2.5%~3.2% —— 低于手册
§7.8 静态天花板 6.17% 一半。七种模型架构横扫全部落在 ±0.02 内（GBDT
等权 / 近期加权 / 物理基展开 / 二者叠加 / Huber / 物理基岭回归 / PLR
分段专家），**架构不是瓶颈**。加功率滞后项（禁用）也只到折均 0.82~0.93。
详见手册 §7.14。

**逐台当前最好（干净口径）**：

| 对象 | 方案 | 实验 | R² | NMBE | 门禁 |
|---|---|---|---|---|---|
| CH01 | hybrid/12 | EXP-0048 | 0.806 | +0.0247 | FAIL(NMBE) |
| CH02 | lab gbdt/15 | EXP-0072 | 0.723 | −0.0051 | PASS |
| CH03 | hybrid/12 | EXP-0050 | −0.098※ | +0.0340 | FAIL(NMBE) |
| CH04 | hybrid/15 | EXP-0070 | 0.641 | −0.0014 | PASS |
| HXBANK | lab gbdt | EXP-0066 | 0.759 | +0.0027 | PASS |

※ 退化折假象（13 样本、CV_y=0.033、单折 R²=−5.21），剔除后七折均值 +0.632。

**本轮实际拿到的**：

- 补齐 3 个白名单特征（`t_cw_tower_out`/`t_chw_return`/`ambient_h`）：
  CH02 R² 0.588→0.682、CH04 0.580→0.641。视图 VIEW-0047~0050。
- 模型实验室首次实战 `gbdt_static@v1`（纯梯度提升，闭集表达不了）：
  板换 R² 0.382→**0.759**、CH02 0.682→**0.723**。
- **修掉实验室通路的目标列泄漏**（见 Change Log）。
- 证伪：`runtime_accum` 带来的 CH01/CH03 NMBE 改善全部来自时间代理吸收
  漂移，摘掉即弹回，双双重新 FAIL。

**未决**：

- ~~RG-0012 白名单仍含 `runtime_accum`~~ —— **已钉正**：新目标 **RG-0015**
  「冷机功耗静态模型（白名单剔除时间代理）」取代 RG-0012，`candidate_inputs`
  由 16 项减为 15 项，DD-16 机器校验通过，判据面与阈值不变。
  （ID 是 RG-0015 而非 RG-0014：RG-0014 被一次契约校验失败的调用占掉了号，
  ID 在校验前分配且永不回收。）
- ~~CH01/CH03 的系统性低估无解~~ —— **已定位病灶**（手册 §7.15）：偏差集中在
  冷却水进水温设定值附近的窄 lift 带（CH01 5.05~5.95、CH03 5.03~5.81），该带
  贡献 73% 的残差和。**不是漂移、不是结垢、不是时间代理能治的**。
  按 lift 分段已试并**证伪**（§7.16）。取证后**结案为测点边界**（§7.17）：
  带内制冷剂侧两个温度通道全部失去激发（`t_evap_out` CV 0.0066 恒定、
  `t_cond_in` 带内 CV 0.010），带内可解释方差显著下降（CH03 单独训练
  R² 0.539 vs 带外 0.910），且数据集不含任何逐台制冷剂侧状态量。
  **继续改模型无效**——只能加装测点（蒸发/冷凝饱和温度、导叶开度），
  或重议这两台的验收口径。
- 通过门禁的三个（CH02/CH04/HXBANK）均未发布 —— 过门禁但不满足
