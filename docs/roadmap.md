# 实施路线图

## 1. 实施原则

- 先建立稳定契约，再增加 Agent 自主性。
- 先实现单机可复现闭环，再引入分布式基础设施。
- 先做一个设备和一个目标变量，再扩展到系统级模型。
- 每个阶段都必须有可执行的验收标准。

## 2. Phase 0：契约定稿

交付：

- TFOM v1 Schema。
- TFDC-XLSX v1 Schema 与模板。
- Research Goal、Experiment 和 Model Package Schema。
- 标准单位表、变量命名规范和错误码。
- 一份冷水机示例物模型和一份小型 Excel 固定测试数据。

验收：

- 所有 Schema 可由程序验证。
- 示例 Excel 能准确映射到 TFOM。
- 非法列名、单位、公式、时间戳和引用能给出稳定错误码。

## 3. Phase 1：数据底座

交付：

- TFDC-XLSX 导入器和验证器。
- 文件指纹和不可变 revision。
- Excel 到 Parquet 转换。
- DuckDB 元数据索引。
- 数据画像和质量报告。
- Dataset View 定义、哈希、物化与复用。

验收：

- 重复导入相同文件可识别相同指纹。
- 修改后的文件创建新 revision，不覆盖旧数据。
- 同一 Dataset View 可重复产生一致结果。
- 原始 Excel 在导入后保持只读、可追溯。

## 4. Phase 2：确定性研究内核

交付：

- Research Ledger。
- Experiment Runner。
- 基线回归、一个物理模型和一个残差混合模型模板。
- 时间切分、设备留出和物理约束验证。
- 模型比较与结构化实验报告。

验收：

- 固定数据、代码、配置和种子可以复现实验指标。
- 每次实验能追踪到完整的数据和研究谱系。
- 不满足硬性物理约束的模型无法进入发布候选。

## 5. Phase 3：Pi/Agent 编排

交付：

- 数据发现、画像、实验执行和模型比较工具。
- Research Goal 到实验计划的编排流程。
- 假设、发现和决策的结构化写入。
- 预算、停止条件和人工审批点。
- 一期单 Agent 多角色工作流。

验收：

- Agent 不直接读取大规模原始数据，只使用工具摘要和有限样本。
- 每个新实验都能引用已有证据和明确假设。
- 达标、预算耗尽和数据不足都能正确停止并输出原因。

## 6. Phase 4：模型注册与部署

交付：

- Model Package 构建和校验。
- 模型版本、状态和发布门禁。
- 通用 `property_code` 到具体 `variable_id` 的部署绑定。
- 算法服务器/SoftPLC 接口适配。
- 线上质量、漂移和物理违规监控。

验收：

- 已发布模型可从空环境按模型包加载并完成推理。
- Excel、API 和现场系统使用一致变量语义。
- 模型可安全回滚到上一生产版本。

## 7. Phase 5：系统化扩展

在单机闭环稳定后再考虑：

- Docker 隔离与任务队列。
- PostgreSQL 元数据、MinIO/S3 制品和 Kubernetes Worker。
- 多项目、多站点和权限隔离。
- 多 Agent 并行提出候选模型。
- 系统拓扑和多设备联合物理模型。
- 在线数据接入、主动学习和重新研究触发器。

这些演进不应改变 TFOM、TFDC、Experiment 和 Model Package 的核心语义。

## 8. 推荐首个垂直切片

建议以“冷水机输入功率模型”为第一个完整用例：

```text
输入：
  冷冻水供回水温度、流量
  冷却水供回水温度
  制冷量、室外湿球温度

输出：
  输入功率

候选：
  线性基线
  Q / COP 物理模型
  物理模型 + XGBoost 残差

验证：
  时间外推
  低/高负荷
  留一冷水机
  功率范围、COP 和单调性约束

交付：
  可复现实验 + Model Package + API 签名
```

该切片能同时验证数据契约、物模型、研究闭环、混合建模和部署签名，是一期最有价值的端到端样板。
