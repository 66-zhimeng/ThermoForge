# ThermoForge V2 实现与验证

日期：2026-09-06。软件版本 `2.0.0`，开发分支 `codex/thermoforge-v2`。

V2 交付独立后台服务与六个 Codex 研究实例，GUI、CLI、网页副驾与外部 MCP 连接同一服务。
插件是操作入口，后台研究不依赖插件连接存活。原 V1 修改已先分功能提交并推送 `harness-schemes`；
V2 分支起点为 `be16ff1`，原运行代码基线为 `1953326`。

## 工程与研究边界

| 项目 | 当前实现 |
|---|---|
| 智能体后端 | Codex App Server `0.153.4`，一个主进程与五个候选进程，各自持久会话；可配置单 Codex 对照 |
| 进程与通信 | Windows 隐藏启动；只初始化阶段顺序建立权限，研究回合并行；动态工具与消息经过 ThermoForge |
| 调度归属 | 独立本机服务、OS 排他锁、SQLite 状态与预算事务；客户端退出后服务继续 |
| 研究能力 | 文献搜索/公开 HTML、文本、PDF 读取，来源登记，想法、父子谱系、模型提交、实验、发现、报告 |
| 实验内核 | 复用 V1 数据白名单、子进程训练、统一指标、物理检查及 lab 五连检；全局训练 worker 固定 1 |
| 同口径比较 | 固定目标、数据修订、视图、环境、种子、切分和特征；记录实际模型与推理配置并用于恢复 |
| 搜索反馈 | 只向研究智能体返回 validate；关闭会让训练接触最终留出段的旧 rolling CV 路径 |
| 最终留出 | 运行 completed/cancelled 后，外部报告先按 validate 选定实验，再读取该实验 A/B/C；不反馈给六实例 |
| 记忆和策略 | 运行内私有/显式共享证据、父路线、Top-K 实验排序与去重路线、预定义探索/改进/组合建议 |
| 报告 | 每候选及主报告，JSON/Markdown/自包含 HTML；保留来源、失败、缺失指标、选择理由和适用限制 |

公开资料是研究数据，不是工具权限指令。想法必须登记研究理由、预测与反证条件，来源可为资料、历史或明确的自主猜想。
记录可核验理由和工具事实，不要求保存模型私有内部思维链。提交者提供的摘录不会被标成工具已核验全文。

暂停/取消在领域工具结束、实验归账后完成；排队实验在真正开始训练前再次检查状态。
失败、已预留但因控制取消的作业均计入实验预算，重复幂等键不会重复训练或扣账。
token 默认上限 1,000,000，累计输入输出（含缓存输入）；这是软预算，在途请求存在超额窗口，不等于费用。
服务不购买额度或自动增加预算。未知用量不按零费用解释。

命令：`.venv/Scripts/python.exe -m pytest -q --basetemp=.pytest_v2_root_release`。

真实完整研究闭环另以隔离的 600 步合成冷机数据进行，通过真实 Codex → ThermoForge 领域工具 → 训练子进程 → 报告验证。
这项验收验证软件闭环，不能代替多设备、重复运行、同预算的研究质量基准。

实际运行 `RUN-5dacd6239bed44ec` 完成五个 linear 与五个 ridge 实验、十个想法和十个发现。
首次在 800,000 token 配置下停止，实际 811,672；恢复时发现 Codex 的 `usage.total` 会按新进程重新累计。
软件现将前段消费持久保存为基数，再合并当前进程累计值；重复通知不重复扣账，旧进程迟到通知不覆盖新段。
验收旧账本以保留的两段原始用量进行一次透明校正，记录证据哈希和修正事件；原实验与原始快照均不覆盖。

另发现第一阶段报告可能被误当成最终报告，已改为必须覆盖本轨迹全部已结算实验；主最终报告还需在候选阶段结束后生成。
实验预算已用尽但报告未完成时，剩余 token/回合预算可用于补报，无需重新训练。

该运行最终 **completed，严格验收通过**：

- 5 条候选各完成 linear → ridge 两次真实训练，保留 10 个想法、10 个发现。

- 新进程恢复原会话，10 次旧实验记录逐字段不变；只恢复缺少报告的 candidate-4、candidate-5 和 main，补报后全部退出。

## 兼容范围与保留工作

- 已实测 Windows、本机 Codex `0.153.4` 与当前默认模型。其他 Codex 版本须重新核验协议后加入支持范围；旧 `0.151.0` 在本机被当前模型拒绝。
- Windows 优先发现桌面应用自带且已验证的 CLI；`TF_CODEX_BIN` 可显式指定。`prepare` 发现可执行文件与所需版本，实际协议和认证在实例启动时检查。
- Windows 服务使用 Job Object 回收服务退出后的子进程。POSIX 存在基本启动和文件锁支持，但尚未进行平台级崩溃回收与六实例真实验收。
- Codex 权限配置与软件工具门禁用于限制可见资料；这不等同把整个 App Server 放进独立 OS 沙箱。lab 代码仍采用 V1 已接受的 AST 粗筛与子进程约束。
- 运行内证据与路线调整可用；跨运行自动知识库检索、任意新搜索策略生成、完整 EvoX 元进化、其他模型后端仍属后续扩展。
- 尚不宣称六实例优于单 Codex 或 V1。应分别比较后端变化、总算力变化和多智能体机制，记录验证/留出质量、重复性、时间与成本。

## 重现入口

```powershell
uv sync
.venv/Scripts/python.exe -m pytest --basetemp=.pytest_v2_validation
.venv/Scripts/python.exe scripts/verify_v2_codex.py
.venv/Scripts/python.exe scripts/verify_v2_research.py --token-budget 2000000
```

后两个命令会使用本机 Codex 登录并消耗模型用量，不属于默认离线测试。
研究脚本使用仓库测试夹具生成合成数据，各次输出独立目录，不覆盖正式 Vault 或用户实验。
