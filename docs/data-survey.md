## 3. 关键发现

### F1 制冷量是电流百分比的线性重标定（R3）

冷水主机的 `load` 列不是测量值，而是公式：

```excel
K5 = C5*9672/100        ' load = 电流百分比 × 96.72
```

对全部 4 台冷机、全部运行样本验证：`load / 电流百分比` 的**不同取值只有 1 个**，恒等于 `96.72`。

同时 `power` 与 `电流百分比` 高度线性：

| 冷机 | 运行样本 | power ~ a·电流% 的 R² |
|---|---:|---:|
| chiller_01 | 11,454 | 0.9655 |
| chiller_02 | 8,055 | 0.9872 |
| chiller_03 | 11,125 | 0.9584 |
| chiller_04 | 12,358 | 0.9741 |

**决定性证据**：用 `load` 和用 `电流百分比` 预测总功率，得到**完全相同**的指标（R² = 0.96633，CVRMSE = 0.0483，MAPE = 0.0435）——因为它们是同一个电信号的两种刻度。

这正是 [risks.md R3](./risks.md) 描述的陷阱，而且它会**"通过"验收**：MAPE 4.35% < `mape_max: 0.05`。若按 [research-loop.md §1](./research-loop.md) 的候选输入清单（含 `cooling_capacity`）直接建模，系统会输出一个指标漂亮、物理内容为零的模型，且没有任何自动检查会拦住它。

### F2 没有单机流量，冷却水流量为推导值且为负（R2）

冷水主机的全部属性：`power`、`电流百分比`、`status_run`、`electricity_accum`、`runtime_accum`、`fault_alarm`、`status_maintenance`、`condenser_return_t`、`evaporator_supply_t`、`load`。

**没有蒸发器流量、没有冷凝器流量、没有蒸发器回水温度、没有冷凝器供水温度。**

全系统只有两处流量：

- `冷冻水总管.f`（chw_A1 / chw_A2）——字面值，是整个数据集的主要驱动量。
- `冷却水总管.f`——**公式**，由冷冻水侧热平衡反算，且 **最小值 = −1837.83 m³/h**（负流量，物理不可能，对应 `TFDC-602`）。

因此 `P = Q/COP` 这类单机物理模型在本数据上无法标定。

### F3 四台冷机的温度输入完全相同（R5）

单机温度也是公式：

```excel
I5 = IF(D5=1, (冷却水总管!$D5+冷却水总管!$G5)/2, 0)          ' condenser_return_t
J5 = IF(D5=1, (冷冻水总管!$B5*$C5+...)/(...), 0)             ' evaporator_supply_t
```

四台冷机引用**同一组表头单元格**，只是各自的 `status_run` 作为开关。运行时四台的 `evaporator_supply_t` 与 `condenser_return_t` 数值相同。

后果：留一设备验证（[research-loop.md §6](./research-loop.md) 的测试面 B/C）在本数据上**不成立**——设备之间唯一的差异是各自的功率与电流，输入侧没有任何区分度。

此外运行台数几乎恒定：

| 运行台数 | 样本数 | 占比 |
|---:|---:|---:|
| 1 | 410 | 2.7% |
| 2 | 976 | 6.5% |
| 3 | 13,512 | **90.6%** |
| 4 | 15 | 0.1% |

「不同设备组合」这一验证维度同样无法覆盖。

### F4 诚实基线：MAPE ≈ 8.9%，而非 5%（R1、Q9）

剔除 `load` 与 `电流百分比` 后，用表头量预测运行冷机总功率。时间切分（前 70% 训练、后 15% 测试），普通最小二乘：

| 模型 | R² | CVRMSE | NMBE | MAPE |
|---|---:|---:|---:|---:|
| **[循环]** P ~ load | 0.9663 | 0.0483 | +0.0247 | **0.0435** |
| **[循环]** P ~ 电流% | 0.9663 | 0.0483 | +0.0247 | 0.0435 |
| [诚实] P ~ 冷冻水 ΔT | −4.70 | 0.6282 | −0.5705 | 0.7130 |
| [诚实] P ~ 冷冻水 f, t_supply, t_return | −8.47 | 0.8097 | −0.7534 | 0.9049 |
| [诚实] ＋冷却水温度 | 0.7917 | 0.1201 | +0.0334 | **0.0891** |
| [诚实] ＋室外温湿度 | 0.7836 | 0.1224 | +0.0260 | 0.0940 |
| [物理] P ~ Q＋温升 | 0.3316 | 0.2151 | −0.1707 | 0.2173 |
| [物理] P ~ Q＋温升＋交叉项 | 0.4318 | 0.1983 | −0.1514 | 0.1984 |

其中 `Q` 由表头独立算出（`f × 4.186 × ΔT / 3.6`），不使用 `load`。

三点结论：

1. **`mape_max: 0.05` 在线性基线下不可达**。非线性模型会更好，但 4.35%（循环）与 8.91%（诚实）之间的差距说明目标值当初很可能是在循环特征下估出来的。
2. **冷冻水侧单独使用时 R² 为负**（−4.7、−8.5），即比直接用均值预测还差。信息主要来自**冷却水温度**——加入后 R² 从 −8.47 跳到 0.79。这是一条真实且可用的建模发现。
3. NMBE 在多个模型上达到 −0.15 ~ −0.75，量级远超精度指标所暗示的水平。这印证了 [DD-14](./design-decisions.md) 的判断：只看 RMSE/MAPE 会漏掉系统性偏差。

### F5 冷冻水 ΔT 几乎是常数

| 量 | p05 | p50 | p95 |
|---|---:|---:|---:|
| 冷冻水供回水温差 ΔT | 4.57 K | 4.86 K | 5.05 K |
| 冷却水供水 − 冷冻水供水（温升） | 7.46 K | 12.02 K | 16.37 K |

整个制冷季 ΔT 只在 **0.5 K** 区间内变动。负荷变化几乎全部由流量承担。

这有两个后果：一是 `Q = m·Cp·ΔT` 中 ΔT 项没有信息量，制冷量基本等价于流量；二是若换成真实传感器（典型精度 ±0.2 K），0.5 K 的变化幅度将完全淹没在测量噪声中——[implementation-notes §6.1](./implementation-notes.md) 关于守恒容差的担忧在这里得到了具体印证。

### F6 COP 物理不合理

| 口径 | p05 | p50 | p95 |
|---|---:|---:|---:|
| `sum(load) / sum(power)` | 8.95 | 9.99 | 10.80 |
| `Q_表头 / sum(power)` | 8.21 | 11.31 | 27.39 |

水冷离心机组的实际 COP 通常在 5–7 量级，**9–11 不是物理可实现的稳定工况**。同时两种口径对制冷量的估计相差 p50 +10.4%、p95 +62%，彼此不自洽。

`9672` 这个常数（推测为额定制冷量 kW）与冷机功率量级（最大 917–1099 kW）组合出的名义 COP ≈ 9.67，是这个不合理值的直接来源。**在做任何物理建模之前，必须先解决这个量纲/标定问题。**

> **撤销（2026-08-09，数据提供方确认）**：该站点使用的是**高温离心式冷机**，冷冻水供水中位数 17.65 °C（见 §F5 数据），属数据中心高温水工况。此工况下 COP 9~11 物理合理——以 Carnot 上限复核：蒸发侧约 290 K、温升 12~16 K，Carnot COP ≈ 18~24，实测 ~10 约为 Carnot 的 50%，处于正常区间。本节「5–7 量级」的判断误套了常规 7 °C 供水冷机的范围，COP 结论作废。9672 常数与功率量级无矛盾。**遗留**：两种制冷量口径的偏差（p50 +10.4%、p95 +62%）仍然成立，物理建模前仍建议核对口径；I-45 的阈值重标定前提（「待 F6 解决」）自此解除。

### F8 缺失是整段而非随机

`chiller_01.power` 缺失 1,931 个样本（5.51%），分布在 **84 个连续区块**：

| 起 | 止 | 时长 |
|---|---|---|
| 2025-04-11 18:30 | 2025-04-25 14:00 | **331.8 h（13.8 天）** |
| 2025-03-13 16:30 | 2025-03-18 15:15 | 119.0 h（5.0 天） |
| 2025-12-31 18:45 | 2025-12-31 23:45 | 5.2 h |

整段缺失意味着不能用插值填补，只能作为数据空洞排除——这与 [data-contract §6](./data-contract.md)「导入层不做任何插值」的规定一致。

### F9 数据强烈提示为仿真生成

以下证据共同指向该工作簿是由少量驱动序列 + Excel 公式生成，而非现场采集：

- 2,955,883 个公式单元格；绝大多数「测点」是从冷冻水总管、冷却水总管、环境参数三组序列推导出来的。
- `chw_A1` 与 `chw_A2` 的 `t_supply` / `t_return` 序列**完全相同**（min/p50/max 均为 15.36/17.65/18.58 与 21.85/22.59/23.54）；`cw_A1` 与 `cw_A2` 三个属性也完全相同。两条物理独立的总管不可能有逐点相同的测量值。
- `air_inlet_temp` 中位数恰为 24.000，`air_inlet_humidity` 恰好被限制在 44.000–66.000，`fan_frequency` 在 32.003–47.999。
- 「测量」字段带 10 位以上小数（`air_inlet_wetbulb = 18.8506698071`、`fan_power = 721.4380486078`）。
- 全年时间戳完美等距，仅 5.5% 的整段缺失。

**这需要向数据提供方确认**（见 [开放议题 Q10](./open-questions.md)）。若确为仿真数据，其价值在于验证管线打通，而**不能用于标定真实精度目标或验证物理模型**——仿真数据里的「物理关系」是生成它的公式，模型学到的只是这些公式。

## 5. 对方案的影响

### Q8 首个垂直切片

**建议：保留冷水机功率模型，但重新定义输入。**

理由：表冷器末端的 `flow`、`chw_supply_t`、`chw_return_t`、`heat_transfer` **全部是表头公式的副本**，作为建模对象同样退化；泵与风机的 `power ~ status_frequency` 虽然非循环，但只是风机相似定律，信息量太低。相比之下，「运行冷机总功率 ~ 表头工况」是本数据中唯一**既非循环、又非平凡**的关系。

修订后的切片定义：

```text
目标：   运行冷机总功率（sum of chiller.power where status_run = 1）
输入：   冷冻水总管 f / t_supply / t_return
         冷却水总管 t_supply / t_return
         环境参数 ambient_t / ambient_h
         运行台数
禁用：   chiller.load          <- 电流百分比的重标定
         chiller.电流百分比      <- 与目标同源
         chiller.condenser_return_t / evaporator_supply_t  <- 表头公式副本，无设备区分度
验证：   时间外推（4–10 月内切分）
         负荷区间（按表头流量分档）
         不做留一设备验证 —— 本数据不支持
```

### Q9 精度目标

**建议：`mape_max` 从 0.05 修订为基于实测基线的值。**

线性基线在诚实输入下 MAPE ≈ 8.9%、CVRMSE ≈ 0.12。建议初始验收设为 CVRMSE ≤ 0.10、NMBE 在 ±0.02 以内，待非线性模型跑出后再收紧。同时按 [DD-14](./design-decisions.md) 把 NMBE 纳入必报——F4 中多个模型的 NMBE 达到 −0.15 ~ −0.75，仅看 MAPE 完全看不出来。

### 已可确定的 [草案] 阈值

| 参数 | 建议值 | 依据 |
|---|---|---|
| `time_resolution` | `900s`（15 min） | 全表一致，35,039 个步长全为 900 s |
| 数据集时间范围 | 2025-01-01 ~ 2025-12-31 | — |
| 冷机建模可用区间 | 2025-04-11 ~ 2025-10-17 | 14,913 个有效样本（占全年 42.5%） |
| MAPE `y_floor` | 按运行冷机总功率，取 5% 最大值 | F4 中有效样本占比 100%，阈值不敏感 |
| 单文件规模阈值 | 现值（35,040 行 × 最多 72 列）在纯 Python 下数十秒可解析 | 无需提前引入 Parquet |
| 守恒检查容差 | **暂不设定** | ΔT 变化范围仅 0.5 K，且 COP 不自洽，需先解决 F6 |

## 6. 建议的下一步

按优先级：

1. **确认数据性质（[Q10](./open-questions.md)）**——是仿真生成还是现场采集？这决定后续所有结论的适用范围。若为仿真，需另行获取真实数据来标定精度目标。
2. **解决 F6 的 COP 量纲问题**——`9672` 常数的含义与单位。在此之前不要开展物理建模。
3. **修订 Research Goal**：按 §5 剔除循环输入、重设验收条件。
4. **把 F1 的检查固化为自动规则**：在 Dataset View 层检查「目标的上游派生链」，任何与目标共享同一物理量的输入必须显式标记。这条检查若早存在，就能自动拦下本次发现的问题。
5. **实现规范化预处理工具**（[risks.md R8](./risks.md) 的建议 1），把这份工作簿转为 TFDC-XLSX，作为 Phase 0/1 的第一个真实用例。
