# 技能：设备系统辨识（从标签到可交付模型）

> 何时用：标签已经取证干净（见 [[measurement-forensics]]），要从运行数据
> 辨识出设备的物理性能模型 —— 要求能外推、参数可解释、导数符合物理。
>
> 不适用：纯统计预测（`category=data` 的岭回归即可）、数据质量诊断
> （`tf_dataset_modelability`）。
>
> **先读 §1。** 那一节能省掉的算力，比后面所有章节加起来还多。

---

## 1. 定目标之前，先跑朴素基线

**规则：时序数据上的 R² 极易被自相关刷出来。门槛要定在「基线之上的增量」，
不是绝对值。**

实测（冷机功耗，15 min 采样，功率 lag1 自相关 0.99）：

| 方法 | R² | CVRMSE |
|---|---|---|
| **朴素持续 `P[t]=P[t−1]`（零参数、零物理）** | **0.9819** | 3.83% |
| 静态特征（8 个物理量） | 0.9211 | 8.00% |
| 静态 + lag1 | 0.9871 | 3.23% |

**什么都不做就有 R² 0.982，比全部物理量加起来还准。**
「R² ≥ 0.99」在 15 分钟提前量下几乎免费，且完全不代表学到了物理。

多步外推才是诚实的画像 —— 持续基线随步长衰减，静态物理模型不衰减：

| 外推步长 | 15 min | 30 min | 1 h | 2 h | 4 h |
|---|---|---|---|---|---|
| 持续基线 R² | 0.982 | 0.955 | 0.894 | 0.791 | 0.622 |
| 静态模型 R² | — | — | — | — | **0.921** |

**约 1 小时是交叉点。**

### 先问模型是干什么的

| 用途 | 能用滞后项 | 该比的基线 | 本项目可达 |
|---|---|---|---|
| 短程预测 / 异常检测 | ✅ | **朴素持续** | CVRMSE 3.2% |
| **能效优化 / what-if 仿真** | ❌ | **常数均值** | 冷机 8.9~15.2%、板换 **2.8%** |
| MPC 多步滚动 | 仅首步 | 按步长分别比 | 随步长退化到静态水平 |

**静态用途的正确基线是常数均值**（R²=0 那条线），不是朴素持续 —— 后者拿不到。

实测的常数基线与静态模型：

| 对象 | 常数基线 CVRMSE | 静态模型 CVRMSE | 降低 |
|---|---|---|---|
| 冷机 CH01 | 29.10% | 8.87% | 69.5% |
| 冷机 CH02 | 40.96% | 8.99% | 78.1% |
| 冷机 CH03 | 28.43% | 9.06% | 68.1% |
| 冷机 CH04 | 35.63% | 15.19% | 57.4% |
| **板换** | 8.12% | **2.76%** | 66.0% |

> 板换的静态模型 **2.76% 反超朴素持续（2.95%）** —— 这才是「学到了真物理」的
> 标志：它不靠记住上一时刻也能赢。冷机做不到，说明冷机的可解释信息更少。

**换算**：`R² = 1 − (RMSE/σ_y)²` ⇒ `R²=0.99 ⟺ CVRMSE ≈ CV_y/10`。

## 2. 切分方式：按周分块 + purge/embargo

**规则：随机切分虚高，尾部切分把季节外推混进模型误差。**

实测（同一 GBDT，7 特征）：

| 切分 | R² | CVRMSE | 测试集覆盖月份 |
|---|---|---|---|
| 随机打乱 | 0.9709 | 4.61% | 全部 |
| 按天分块 | 0.9635 | 5.71% | 全部 |
| **按周分块 + purge/embargo 3h** | 0.9519 | 6.49% | 5,8,9,10 |
| 尾部 25% | **0.7282** | 14.03% | 仅 9,10 |

- 随机 vs 分块差 0.02 —— 自相关泄漏真实但不主导。
- **主导因素是季节**：尾部切分 R² 掉到 0.73，那不是模型的问题。
- purge/embargo 几乎不改变结果（0.9507 → 0.9519），但要设 —— 它挡的是
  边界处的信息渗透。

> ⚠ 设备季节性运行时，训练集天然缺季节。本项目 A 模式（仅冷机运行）
> **只覆盖 5~10 月**，冷机模型看不到冬季，任何切分都改变不了。

### rolling_cv 的参数怎么配

**先看数据跨度再配，别拍脑袋。** `tf_dataset_get` 的 manifest 里有起止时间。

| 参数 | 怎么定 |
|---|---|
| `initial_train_fraction` | 0.2~0.3。给后面留够折数 |
| `horizon_seconds` | 剩余跨度 ÷ 期望折数。半年数据配 7 天，约 8 折 |
| `step_seconds` | 等于 `horizon_seconds`（不重叠） |
| `max_folds` | 6~10。再多只是摊薄每折样本 |

配错的典型症状：`初始窗口 + embargo 已覆盖全部数据` —— 说明
`initial_train_fraction` 太大或 `horizon` 太长。**报错信息里带了实际
跨度与剩余空间的数字，照着调，不要试错。**

实测可用配置（跨度 188 天、15 min 分辨率）：
`initial_train_fraction=0.3, horizon=step=7 天, max_folds=8` → 8 折全有效。

## 3. 升级阶梯

**逐级往上，每级留 EXP-ID，下一级的假设 `basis` 引用上一级证据。**

| 级 | 模型 | `category` / `physics` | 何时够用 |
|---|---|---|---|
| 1 | 线性基线 | `data` / `ridge` | 建立地板 |
| 2 | DOE-2 三曲线 | `physics` / `cooling_balance_v2` | 有额定参数、工况覆盖宽 |
| 3 | **Gordon-Ng 熵产** | `physics` / `gordon_ng` | 冷机，要可解释参数 |
| 3' | **ε-NTU 换热器** | `physics` / `eps_ntu` | 板换/冷凝器/蒸发器 |
| 4 | 物理 + 残差（单调约束） | `hybrid` / 任一 physics | 物理项已抓住主趋势 |
| 5 | 纯学习器 | `data` | **仅作精度上界参照，不交付** |

第 5 级不作交付：不满足导数约束、不能外推、参数无物理含义。

### 级 3：Gordon-Ng

能量 + 熵平衡 + 换热热阻，三参数全非负，**单调性由方程结构保证**
（`∂P/∂Q>0`、`∂P/∂T_cond>0`、`∂P/∂T_evap<0`，不需额外施加）：

```
T_e = T_ei − Q_e·R_e ;  T_c = T_ci + Q_c·R_c
Q_c = Q_e + P        ;  Q_c/T_c = Q_e/T_e + ΔS_int
⇒ Q_c = T_ci·K / (1 − R_c·K),  K = Q_e/T_e + ΔS_int
```

```json
{"model": {"category": "physics", "physics": "gordon_ng",
           "hyperparameters": {"inputs": "cooling_load,t_evap_out,t_cond_in"}}}
```

> ⚠ **不要用文献里的线性化形式。** 窄工况下 `a0/a2` 高度共线，反解时分母趋零 ——
> 实测 CVRMSE 爆到 **5000%+**。本实现用对功率残差的非线性最小二乘 + 非负约束。

### 级 3'：ε-NTU

只吃**入口端口值**，出口温度是输出 —— 结构上杜绝「出口×流量=标签」泄漏：

```
Q = ε·C_min·(T_h,in − T_c,in)
ε = [1−exp(−NTU(1−Cr))] / [1−Cr·exp(−NTU(1−Cr))]
NTU = UA/C_min,  UA = UA0·(m_h^-0.8 + β·m_c^-0.8)^-1
```

```json
{"model": {"category": "physics", "physics": "eps_ntu",
           "hyperparameters": {"inputs": "t_hot_in=t_chw_in,t_cold_in=t_cw_in,f_hot=f_chw,f_cold=f_cw",
                               "n_units": "run_count"}}}
```

### 级 4：物理 + 残差，带单调约束

```json
{"model": {"category": "hybrid", "physics": "gordon_ng",
           "hyperparameters": {"n_estimators": 400, "max_depth": 4,
                               "monotone_constraints": "cooling_load=1,t_cond_in=1,t_evap_out=-1"}}}
```

### 级 6：模型实验室（开放代码通路）

**阶梯内置闭集穷尽、且 §5 的信息面手段也试过仍不达验收阈值时**，不要停在调超参 ——
自己写一个新模型模块提交到模型实验室，让建模方案本身成为可迭代对象：

1. 按 `thermoforge_models.lab` 的模块协议写一个自包含 Python 模块：定义
   `MODEL_FORMAT`（`thermoforge.lab.` 前缀）、`INPUT_ROLES`（与实验声明的输入列一致）、
   `build_model(hyperparameters, seed)` 与 `load_model(directory)`；模型对象须
   `fit(df, y) / predict(df) / save(dir)`，save 必须写含 `format` 的 model.json，
   **禁 pickle，随机源只用传入的 seed**。
2. `tf_lab_submit`（或 CLI `lab submit --source-file`）：先 AST 源扫描
   （import 白名单、禁 eval/exec/os.system、禁 pickle/动态库/联网下载），再在隔离
   子进程跑五连检（interface / fit_predict / save_contract / roundtrip / determinism，
   位级一致）。通过即 `validated`。
3. **不需要任何人审批，直接开实验**：`model.category="lab"` +
   `hyperparameters.lab="<name>@v<N>"` 即可进 runner，跑的是真实数据、真实时间切分、
   真实指标；源码快照写进实验目录与发布包（`artifact/lab_source.py`），发布模型
   完全自包含、可冷加载。
4. **读指标 → 改代码 → 重交 → 再跑**，这一圈由你自己闭合：源码哈希一变就是新版本
   （`v2`/`v3`…），每版都在 Ledger 里留下自己的实验证据；走不通的版本用
   `tf_lab_deprecate` 停掉，让候选清单只剩还活着的方案。

纪律：

- 实验室模块仍受同一数据契约约束（只用白名单 candidate_inputs 的列），实验室不是
  绕开 §1 基线与 §4 体检的捷径 —— 新方案照样要和朴素基线比增量。
- 校验失败不是"再试一次"，是**代码有问题**：`determinism` 挂了说明你用了无种子随机源，
  `roundtrip` 挂了说明 save/load 丢了状态，按 checks 里的 detail 改，别原样重交。
- 别把实验室当成堆参数的地方：每提一版都要能说清"这版换了哪个物理/统计假设、
  预期改善哪个面的指标"，说不清就不是一次实验，是一次瞎撞。

## 4. 每级实验后必做的三项体检

**只看 CVRMSE 会把两类严重问题放过去。**

### ① 参数体检

**病症一：参数贴死在边界** ⇒ 该项在当前工况下**不可辨识**。

实测 EXP-0022（Gordon-Ng，n=29753）：

| 参数 | 值 | 判读 |
|---|---|---|
| `r_condenser` | 9.5e-4 K/kW | ✓ 工程量级 |
| `delta_s_internal` | 0.99 kW/K | ✓ 工程量级 |
| **`r_evaporator`** | **1.0e-18** | ❌ **贴死下界** |

处理：固定为铭牌值，或明说该项未辨识 —— 别当成「拟合出热阻为零」汇报。

**病症二：量级失控** ⇒ 模型被推到饱和区，参数失去物理意义。

实测 EXP-0021（ε-NTU）：`ua0` = 4.1e6、`beta` = 3.8e5（应为 1~100）。
结论仍对（板换确实跑在有效度极限），但参数不能当换热面积的度量。

> 用 `tf_experiment_get` 读 `fitted_parameters`。**两种病症都不影响 CVRMSE。**

### ② 残差结构

- 与哪些变量还相关？（相关就加进特征）
- **偏度/峰度**：峰度 5~12 说明重尾，误差被少数极端点主导 ——
  此时该去查那些点是什么，而不是改进主体拟合。
- 实测：离群点集中在**启动后前几个时刻**（离群率 30~50%，基线 5%）。

### ③ 物理校验

- 硬门禁 `η ≤ 1`
- 按负荷率**分层**看 η 是否偏离特性曲线（不要比不分层的中位数）
- 对受约束特征做偏依赖，检查导数号

**三项答不上来就别升级** —— 盲目加容量只会把噪声记住。

## 5. 精度不够时，往哪找信息

**堆模型容量已被证明无效。** 本项目实测的四条路全部证伪：

| 猜想 | 做法 | 结果 |
|---|---|---|
| 标签含噪 | 负荷滑动平均 3/5/9 点 | 8.95% → 8.84%，无效 |
| 目标选错 | 改预测 η 再还原 P | 9.63%，**更差** |
| 缺动态项 | 加输入变化率 | 8.90%，无效 |
| 拆分是瓶颈 | 改用**无拆分假设**的池级标签 | 9.53%，**更差** |

最后一条尤其有价值：池级标签精确、不依赖任何拆分假设，**反而更差** ——
说明误差不来自拆分；而且池化会把各台的效率差异混成噪声，**逐台建模是对的**。

### 有效的方向

| 症状 | 手段 | 实测收益 |
|---|---|---|
| 残差与时间/累计运行时长相关 | 加时间索引（捕捉结垢/衰减） | 8.00% → **6.17%** |
| 残差重尾、离群集中在启动后 | 剔除瞬态段 | 8.95% → 8.64% |
| 工况覆盖窄 | 纳入更多工况的数据 | 负荷率下限 0.34 → **0.20** |
| 采样过粗 | 15 min 平均抹平了动态 | 未验证（无更细数据） |

### 承认边界

以下这些堆模型解决不了，要如实写进结论：

- **未测状态量**：导叶开度、压缩机级数、冷媒充注、换热器污垢 ——
  残差重尾最可能的来源。
- **工况覆盖**：本项目冷机负荷率 P5~P95 = 0.34~0.62，**>0.65 无外推依据**；
  满载样本（PLR>0.9）仅 15 行，**容量曲线不可辨识**。
- **探头分辨率**：`condenser_return_t` 步长 0.1 K，比总管温度粗 10 倍。

## 6. 工具面的坑

### 坑一：白名单看不见就别猜

`tf_experiment_plan` 会做 DD-16 校验，但**拒绝信息不告诉你白名单是什么**。
**先调 `tf_goal_get(goal_id)` 读 `candidate_inputs` 原文。**

两种写法语义不同：

| 写法 | 含义 | 对视图的要求 |
|---|---|---|
| 裸 `cooling_load` | 范围内**任意对象**的该属性 | 无 |
| `CH01.cooling_load` | **仅 CH01** | 视图对象范围必须含 CH01 |

实验的 `features` 与 `target` 一律填 **property_code**（不带对象前缀）。
`tf_goal_get` 的 `whitelist_style` 字段直接告诉你是哪种。

### 坑二：physics 家族有四个

`cooling_balance_v1` / `cooling_balance_v2` / **`gordon_ng`** / **`eps_ntu`**。
后两个也可作 `category=hybrid` 的物理项。

### 坑三：`inputs` 的写法

`,` 与 `;` 都是分隔符；省略 `=` 视为同名映射
（`"cooling_load,t_cond_in"` ≡ `"cooling_load=cooling_load;..."`）。

### 坑四：`environment_lock` 不要编

`runtime.environment_lock` 是**机器算出来的**环境指纹，你无从得知。
**留空**（`""`）即可 —— `tf_experiment_plan` 会填当前机器的真值，并在
`summary.environment_lock` 回报填了什么。

编一个字符串的后果：每次 `tf_experiment_run` 都报 **TFX-901**
（实测编出 `sim-2026-08-default`，连撞两次直到放弃）。
只有在**刻意复现另一台机器的历史实验**时才手写它 —— 那正是 TFX-901
要守的场景。

`random_seed` 相反：**必须自己写**。它是研究决策，缺了报 TFX-902，
工具不会替你填。

## 7. 标准工作流

```
tf_status                      # 看进展
tf_goal_get <RG-ID>            # **必做**：读白名单原文与验收门槛
tf_dataset_schema <建模集>      # 确认列名与 source_kind
tf_dataset_modelability        # 语义门禁，FAIL 不得建模
  ↓ 定目标前先跑基线（§1）：常数均值 + 朴素持续
tf_goal_create                 # acceptance 设在基线之上的增量
tf_hypothesis_create           # 写明路线与导数约束
  ↓ 逐级升级（§3），每级：
tf_experiment_plan → tf_experiment_run → tf_experiment_get
  ↓ 每级做 §4 的三项体检，不合格不升级
tf_model_compare
tf_model_publish               # 只发布通过全部校验的
```
