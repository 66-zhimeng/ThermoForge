# 技能：现场数据取证（建标签之前必须做的事）

> 何时用：拿到一批现场运行数据，要从中构造出**可信的建模标签**。
> 典型场景：某设备的负荷/换热量没有直接测点，只能由能量平衡推出来。
>
> 不适用：标签本身就是直接测量值（那就直接建模，用
> [[system-identification]]）。
>
> **这份技能的全部内容都来自踩坑。** 每条规则后面都附了当时的错误结论与
> 推翻它的证据 —— 因为「为什么」比「是什么」更难重建。

---

## 0. 一句话总纲

> **标签错了，模型再好都是在拟合错误。**
> 一个项目里花在标签取证上的时间，应当远多于花在调模型上的时间。

实测代价：在下面这批数据上，冷量拆分的口径改了**三次**才站得住；
每次改动都让「冷机制冷量」这个标签的中位数变化 30% 以上。
而模型侧从线性换到 GBDT 再换到物理模型，CVRMSE 只在 8%~15% 之间晃。

---

## 1. 同名不同物：先做测点取证

**规则：变量名不可信，只有数值关系可信。**

现场数据里的列名往往是按「物模型模板」批量生成的，与该测点实际接在哪根管上
无关。建模前必须逐条核实。

### 取证手法（按可信度排序）

| 手法 | 怎么做 | 能判定什么 |
|---|---|---|
| **逐位相等率** | 两列在双方非空处 `\|a−b\|<1e-9` 的比例 | 一列是否是另一列的副本 |
| **相等率 vs 运行占比** | 相等率是否恰等于该设备的运行时间占比 | 该测点是否「开机时读总管值」 |
| **反算残差** | 用能量平衡反推某列，与表中值逐点比 | 该列是实测还是算出来的 |
| **量化步长** | `np.diff(np.unique(v))` 的最小值 | 探头分辨率；步长突变说明来源不同 |

### 实测发现（这批数据）

| 现象 | 判定 |
|---|---|
| `chiller_0i.evaporator_supply_t` 与总管供水相等率 = 该机运行占比 | 它不是单机测点，是**开机时读总管** |
| `hx_0i.cw_supply_t` 与总管冷侧 \|差\| 中位 **0.00 K** | **纯副本**，无独立信息 |
| `hx_0i.cw_return_t` 与总管热侧 100% 逐位相同 | **错列**，不可用于拆分 |
| 反算冷却水供水温，误差中位 **0.000000 K** | 冷却侧**由冷冻侧热平衡算出**，不能自证 |
| `condenser_return_t` 步长 0.1 K，总管温度 0.01 K | 粗 10 倍，是逐台标签的精度瓶颈 |

> **最贵的一次误判**：曾把 `hx_0i.cw_return_t` 当作板换出水温用于拆分。
> 它实际是总管热侧的副本，导致板换段温升取成 6.5 K（真值 A 模式 0.20 K）。
> 修正后才发现真正的中间温度在 `condenser_return_t` 上。

## 2. 先辨识工况，再辨识模型

**规则：混了工况的标签，任何模型都学不到东西。**

同一批数据里往往有几种拓扑上不同的运行方式。它们的能量流向不同，
**标签的计算式也不同**。不分开就等于把几个不同的函数强行拟合成一个。

### 辨识工况的信号，按可靠度排序

1. **拓扑约束推出的台数关系**（最可靠）。例：泵与设备串联 ⇒
   `在运板换台数 = 运行泵数 − 运行冷机数`。实测该式与状态位一致率 **99.6%**，
   且「泵数 < 冷机数」的反例为 **0**。
2. **设备状态位**。可用但会漏报，须与 ①交叉核对。
3. ~~效率指标（如 COP 超过物理上限）~~ —— **不可靠，见 §4**。

### 工况划分后要立刻做的事

对每个工况，问一句「**这个工况下，哪个量应当为零？**」
那就是你的判决性检验（§3）。

---

## 3. 校验必须来自体系之外

**规则：用体系内的等式去验证体系内推出的结果，是循环论证。**

### 反面教材：闭合检验

`Q_a + Q_b ≡ Q_total` 这类检验看着很硬，多数是**恒等式**。

实测证据：把 `Q_hx` 强行取成总量的 **0% / 50% / 100%**，闭合比都是 **0.9997**。
因为 `Q_a + Q_b = (总量 − Q_b) + Q_b ≡ 总量`，与 `Q_b` 取什么值无关。

> 判断方法：把待验证的量换成一个明显错误的值，若检验仍然通过 —— 它是恒等式。
> **每次引入新的「闭合检验」前，先做这个测试。**

### 正面手法（按强度排序）

**① 「应当为零」工况（最强，可一票否决）**

找一个物理上该量必为零的工况，看算出来是不是零。

实测：B 模式（无冷机运行）下冷却侧全部吸热必然来自板换，正确口径应给 **100%**。
三种候选口径分别给出 **38% / 62% / 100%** —— 一次性判掉两个错误口径。
这一条比之前所有检验加起来都有用。

**② 跨工况的无量纲一致性**

同一台设备在不同工况下，**无量纲效率**应当落在同一带内。
用卡诺效率 `η = COP / COP_carnot`，硬门禁 `η ≤ 1`（热力学第二定律）。

**③ 参数量级体检** —— 见 [[system-identification]] §4.6。

### ⚠ 比较前必须分层

**规则：效率随负荷率系统性变化，跨工况比中位数会得出相反结论。**

实测教训：曾因 C 模式整体 η（0.181）低于 A 模式（0.239）而判定拆分错误。
**按负荷率分层后**，同层的 C/A 比值是 **0.91~1.01** —— 两者一致，
整体差异只是因为 C 模式落在低负荷区。**这个误判导致一整轮返工。**

## 4. 不要用「物理上限」当工况判据

**规则：教科书上的典型值区间，不是该机组的物理上限。**

实测最深的一个坑：发现某工况下 47.5%（6428 点）的表观 COP 超过 11
（该站的「物理区间 9~11」），据此判定这些点混入了自由冷却，逐出训练集。

**该结论错误。** 两条独立证据推翻：

1. **泵台数否认** —— 这 6428 点中 `n_泵 − n_冷机 = 0` 的占 **100%**。
2. **卡诺效率一致** —— COP>11 组 η=0.264，COP≤11 组 η=0.278，几乎相同；
   COP 差异**完全由提升温差解释**（5.13 K vs 8.58 K）。全集 `η>1` 的点为 **0**。

**错因**：环境温度是混杂因子。天冷 → 冷凝水温低 → lift 小 → COP 真实地高；
同时天冷 → 自由冷却可行。**把相关当成了因果。**

> 该站冷冻水供水 17.6 °C 偏高，lift 常低至 5 K，此时 COP 15~16 完全正常。
> 判据要用**无量纲**的 η，不要用有量纲的 COP。

## 5. 数据集怎么落盘

标签算好之后，把它作为**正式数据集**落盘，而不是留在脚本里。理由：
下游（智能体、实验）不该重做工况辨识。

### 三条硬要求

1. **每列显式标注 `source_kind`**：直读测点为 `measured`，公式算出为
   `estimated`。白名单门禁（DD-16）靠它防循环论证。
2. **只保留有效时刻，不要保留全年时间轴。** 设备季节性运行时，
   空窗会让滚动交叉验证的早期折整折为空。
   实测：35040 → 14926 行后，实验才跑得起来。
3. **加工况标识列**（如 `hx_run_count`）。不同工况的标签有系统性偏差时，
   这一列让偏差**可归因**，而不是混成噪声。

### lineage 里必须写清楚

- 源数据集与 revision
- 用到了哪些假设（编号引用）
- 哪些工况的标签口径不同

## 6. 假设登记表

**规则：每条假设都要能被单独复核和推翻。**

散在代码里的假设等于没有假设。集中登记，每条五个字段：

| 字段 | 作用 |
|---|---|
| **内容** | 假设了什么（公式级别，不是描述级别） |
| **依据** | 为什么这么假设（现场信息 / 数据证据，分开写） |
| **影响范围** | 哪些结论依赖它 |
| **失效后果** | 它错了会怎样（量化，不要写「结果会不准」） |
| **复核方式** | 用什么检验能发现它错了 |

本项目登记了 13 条（A-01..A-13），其中 **2 条已废弃、3 条被推翻后重写**。
废弃的要保留并标注理由 —— 否则下一个人会重走一遍。

参见 `docs/data-processing-handbook.md` §6。

## 7. 检查清单

建模之前逐条过：

- [ ] 每个要用的测点都做过取证（§1），确认名字与实际接管一致
- [ ] 工况已划分，划分依据比状态位更可靠（§2）
- [ ] 每个工况都找到了「应当为零」的量，并通过（§3①）
- [ ] 引入的每个闭合检验都做过「换成错误值仍通过吗」测试（§3）
- [ ] 跨工况比较都做了分层（§3⚠）
- [ ] 没有用有量纲的效率指标当判据（§4）
- [ ] 数据集有 `source_kind`、无空窗、带工况标识（§5）
- [ ] 假设登记表完整，每条都有可执行的复核方式（§6）
